# Инструкция для ИИ: как писать скетч для конвертера ino2ubi

Конвертер превращает один Arduino-скетч (`.ino`) в пользовательский блок FLProg (`.ubi`).
Он не компилирует код, а разбирает текст по правилам ниже. Пиши скетч строго по ним.

## 1. Структура файла (именно в таком порядке)

1. Комментарий в самом начале файла (`/* ... */` или строки `//`). Он станет описанием блока.
2. `#include ...`
3. `#define ...`
4. Глобальные переменные и объекты.
5. Функции, `void setup()`, `void loop()`. Пользовательские функции можно ставить до `setup`/`loop` и после `loop`.

Всё, что стоит до первого `setup` или `loop`, считается глобальной секцией. Глобальные переменные пиши только там.

```cpp
/* Описание блока: что он делает */
#include <Servo.h>
#define SPEED 50          // par скорость по умолчанию

bool door = false;        // in датчик двери
int relay = 0;            // out реле
int delayMs = 500;        // par пауза, мс
unsigned long t = 0;

void setup() {
  // ...
}

void loop() {
  // ...
}
```

## 2. Роли входов, выходов и параметров

Роль задаётся комментарием в той же строке, что и объявление:

| Комментарий | Роль |
|---|---|
| `// in текст` | вход блока |
| `// out текст` | выход блока |
| `// par текст` | параметр блока |
| нет маркера | внутренняя переменная |

- Маркер пиши отдельным словом: `// in`, `// out`, `// par`. Слова вроде `// input` не считаются маркером.
- Текст после маркера (`// in датчик двери`) попадёт в поле «комментарий» входа, выхода или параметра, а также останется комментарием в коде.
- Одна переменная на строку, если у неё есть маркер. Маркер действует на всю строку.
- `#define` тоже может быть параметром: `#define SPEED 50 // par скорость`.
- Имя `En` не используй: оно зарезервировано под вход разрешения (`if(En)`).

## 3. Типы переменных

Входами, выходами, параметрами и обычными переменными становятся только объявления с такими типами:
`int`, `long`, `unsigned long`, `bool`, `boolean`, `float`, `double`, `byte`, `char`, `String`, `uint8_t`, `int16_t`, `uint16_t`, `int32_t`, `uint32_t`.

Инициализатор пиши в той же строке: `int x = 5;`

Эти объявления переносятся в блок declare как есть, в исходном порядке, и ролей у них нет:
- указатели: `uint16_t* q = nullptr;`
- массивы: `uint16_t buf[LIMIT];`
- константы `const ...` без маркера роли (так массив может ссылаться на константу: константу пиши перед массивом)
- объекты и конструкторы: `Servo s;`, `U8G2_... u8g2(...);`
- `static`-переменные

Если нужно, чтобы константа была параметром, пометь её `// par`. Но тогда она окажется после массивов и массив с ней в размере не соберётся.

## 4. Функции

- `void setup()` и `void loop()`: пустые скобки, без параметров.
- Тип возврата только из списка: `void`, `int`, `long`, `bool`, `boolean`, `float`, `double`, `byte`, `char`, `String`, `uint8_t`, `int16_t`, `uint16_t`, `int32_t`, `uint32_t`. Вместо `unsigned long` пиши `uint32_t`.
- Параметры простые: `тип имя`, через запятую. Без указателей, ссылок (`int&`) и значений по умолчанию.
- Открывающую `{` ставь после закрывающей `)`.

## 5. Чего избегать

- `{` и `}` внутри строковых и символьных литералов: конвертер считает фигурные скобки и собьётся.
- `#if`, `#ifdef`, `#pragma` и другие директивы кроме `#include` и `#define`: они игнорируются.
- Исполняемого кода на глобальном уровне. Он должен быть внутри функций.
- Объявлений глобальных переменных после `setup`/`loop`: они не попадут в блок.
- Блокирующих `delay()` в `loop`: лучше `millis()`. Это не требование конвертера, а совет для работы блока в FLProg.

## 6. Чек-лист перед выдачей

- [ ] В начале файла есть комментарий-описание.
- [ ] Все глобальные объявления стоят до `setup`/`loop`.
- [ ] Входы, выходы и параметры помечены `// in`, `// out`, `// par`, по одному на строку.
- [ ] Типы переменных из списка в разделе 3, нет имени `En`.
- [ ] Типы возврата и параметры функций простые.
- [ ] Нет `{` и `}` в строках, нет `#if`/`#ifdef`.
