# Блок FLProg из скетча

Цель: пользователь описывает, что должен делать блок, а ты отдаёшь готовый файл `.ubi`.

## Шаги

1. Если пользователь дал готовый `.ino`, возьми его. Иначе напиши скетч сам.
   Перед написанием прочитай `rules.md` рядом с этим файлом и следуй ему строго
   (структура, роли `// in`, `// out`, `// par`, допустимые типы, ограничения).
2. Сохрани скетч в файл `<имя>.ino` в рабочей папке пользователя. Первым в файле идёт комментарий-описание блока.
3. Запусти конвертер:

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/ino2ubi.js" <имя>.ino -o <имя>.ubi --name "Название блока"
   ```

   Флаг `--en` добавляет вход `En`: код в `loop` выполняется только при `En`. Добавляй его, только если пользователь просит условие запуска.
   Флаг `--desc "..."` задаёт описание. Без него берётся комментарий в начале скетча.
4. Прочитай сводку конвертера (входы, выходы, параметры, переменные, функции) и сверь с замыслом.
   Если роль определилась не так, исправь маркеры в скетче и запусти конвертер снова.
5. Ответь пользователю: путь к `.ubi` и `.ino`, список входов, выходов и параметров, что блок нужно импортировать в FLProg (библиотека блоков).

## Важно

- Результат не проверен в FLProg автоматически. Скажи об этом прямо, не утверждай, что блок точно откроется.
- Если конвертер завершился с ошибкой, покажи её текст и исправь скетч, а не обходи ошибку.
- Не меняй файлы в папке плагина.
